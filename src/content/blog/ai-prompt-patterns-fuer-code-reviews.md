KI-Tools als zusätzliches Augenpaar im Review-Prozess einzusetzen, kann echten
Mehrwert bringen – wenn die Prompts gezielt statt generisch sind.

## Muster 1: Die Gegenperspektive einnehmen

Statt "Findest du Bugs in diesem Code?" frag gezielt: "Welche Annahme in
diesem Code würde bei einem Edge Case brechen?" Generische Fragen liefern
generische Antworten; spezifische Fragen zwingen zu spezifischem Denken.

## Muster 2: Die Rolle wechseln

"Review diesen Code aus der Perspektive von jemandem, der ihn in zwei Jahren
ohne Kontext warten muss." Dieser Rollenwechsel bringt oft andere Aspekte
hervor als eine reine Korrektheitsprüfung – etwa fehlende Kommentare oder
verwirrende Namensgebung.

## Muster 3: Vergleich statt offene Frage

Wenn du zwischen zwei Implementierungen unsicher bist, lass beide gezielt
gegenüberstellen: "Vergleiche diese zwei Implementierungen bezüglich
Lesbarkeit, Performance bei großen Listen und Testbarkeit." Das liefert eine
strukturierte Entscheidungsgrundlage statt einer vagen Empfehlung.

## Die Grenze: Verantwortung bleibt menschlich

Ein KI-Tool kann Hinweise liefern, aber die Entscheidung, ob ein Review
bestanden ist, bleibt bei dir und deinem Team. Prompt-Patterns wie diese
verbessern die *Qualität der Hinweise* – sie ersetzen nicht das
Verantwortungsbewusstsein im Review.
